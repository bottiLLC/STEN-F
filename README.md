# STEN-F (Simple Tough Effective Next-generation Finance)

[![CI](https://github.com/bottiLLC/STEN-F/actions/workflows/ci.yml/badge.svg)](https://github.com/bottiLLC/STEN-F/actions/workflows/ci.yml)

**STEN-F** は、既存のクラウド会計ソフト（SaaS）によるデータの抱え込みや不自由なエコシステムから開発者・ベンチャー企業を解放するために生まれた、**100% Pure Python 製のオープンソース経理・会計アプリケーション**です。

モダンなフロントエンド/バックエンドを1つの言語で記述できる **Reflex** を GUI フレームワークに採用し、**Clean Architecture（クリーンアーキテクチャ）** に基づいて構築されています。データはすべてローカルの SQLite（非同期 SQLAlchemy 2.0）に保存され、所有権を開発者自身が完全に制御できます。

## 🏴 開発・運用哲学 (Philosophy)

1. **This is your Stengun (これはステンガンだ):** シンプルで、タフで、実戦で勝つための武器（[ステン短機関銃](https://ja.wikipedia.org/wiki/%E3%82%B9%E3%83%86%E3%83%B3%E7%9F%AD%E6%A9%9F%E9%96%A2%E9%8A%83)）のように、過剰な装飾を削ぎ落とした強靭なシステムを目指します。
2. **Of course it's free (当然無料だ):** 基本的な経理・会計ソフトは、自らの手でホストでき、完全に無償であるべきです。
3. **No Vendor Lock-in (ベンダーロックインを排除する):** あなたの財務データは人質ではありません。生の SQL や使い慣れたスクリプトからいつでも瞬時にアクセス可能であるべきです。
4. **Local First (ローカルファースト):** ネットワーク障害やサービス終了に怯える必要はありません。データもアプリケーションも手元で動き続けます。
5. **Don't pay for apps, pay for AI (アプリではなくAIに払う):** 毎月の定額利用料を支払うくらいなら、あなたの業務を真に自動化・高速化する「AI推論（OCRによる仕訳候補抽出）」の従量制API利用料に直接支払うべきです。

## ⚡ 主な機能 (Key Features)

### 1. 経理・会計の基本機能
- **高速なキーボードフレンドリー仕訳入力:** 貸借の自動バランス検証を備えた直感的な入力 UI。
- **マルチタスク「別タブ」アプローチ:** Reflex の SPA 構成を活かし、仕訳入力を遮ることなく、別タブで仕訳履歴の確認、検索、CSV 出力が可能。
- **期首残高（B/S）設定:** 会計年度開始時の資産・負債・純資産の残高を、貸借対照表の完全一致検証付きで登録可能。
- **柔軟な会計年度締め (Fiscal Year Closing):** 既存年度の編集や、次期名称を動的に指定した安全な年度締め処理（次期繰越処理の自動化、CLOSED ステータスへの移行）。
- **セーフガード:** 締めた「CLOSED」な会計年度に対する追加入力・修正をシステムレベルで自動ブロック。

### 2. 電子帳簿保存法 & インボイス制度への対応
- **変更履歴の監査トレール（論理削除）:** 電子帳簿保存法で要求されるデータの訂正・削除履歴の確保に対応。一度登録した仕訳データはデータベース上に論理削除 (`is_deleted`) としてマークされ、いつでも監査証跡をトレース可能。
- **インボイスT番号管理:** 取引先ごとに適格請求書発行事業者登録番号（T番号）をマスタ管理し、仕訳時に自動関連付け。
- **証憑ファイルの永久保存:** 取引に紐付けたレシートや領収書の画像・PDF ファイルを、規則的な命名規則に従ってローカルディスクへ自動的に保存・紐付け。

### 3. レポート＆ PDF 出力
- **各種財務レポーティング:** 合計残高試算表 (Trial Balance)、貸借対照表 (B/S)、損益計算書 (P/L) の自動集計。
- **総勘定元帳 (General Ledger):** 特定期間や特定の勘定科目にドリルダウンして取引の流れを追跡。
- **決算書 PDF 非同期生成 (Offloading):** 重たい PDF 生成プロセスは非同期タスクとしてバックグラウンド処理されるため、帳票出力中も UI がフリーズせず操作を継続可能。

### 4. 🤖 賢い AI OCR 自動仕訳機能 (Powered by OpenAI)
システム設定画面から OpenAI API キーを登録することで、レシートや請求書の画像から自動的に高精度な仕訳を生成します。
- **Native PDF サポート:** PyMuPDF (`fitz`) を利用し、PDF 形式 of 領収書 of 最初の1ページを自動的に PNG 画像へレンダリングして OCR に送信。
- **スマート画像最適化:** API のトークン消費量を削減しつつ、読み取り精度を最大化するため、画像を自動でリサイズおよび DPI 圧縮（長辺2000px制限、DPI 200制限）。
- **スマート取引先マッチング:** 読み取った店舗名から「株式会社」などの法人格や不要なスペースを正規化して除去 (`_normalize_name`)。マスタの登録キーワードと曖昧照合を行い、一致した場合はインボイス登録番号（T番号）やマスタ定義済みの推奨科目を自動適用。
- **LLM によるフォールバック推論:** マスタに存在しない新規取引先の場合でも、登録された勘定科目一覧から LLM が適切な貸借科目を自動推論。日本の個人事業主・小規模法人の実態に配慮し、代表個人による立替を前提とした「役員借入金」の優先適用ルールや、「車両運搬具」などの不適切科目の意図的な除外などのカスタムプロンプト設計を実装。
- **自己修復型バリデーション (Self-Healing Validation):** 消費税額の再計算（税抜額・税率整合性）、日付フォーマット、インボイスT番号の形式を自動でクロスチェック。不整合検知時には `needs_manual_review` フラグを立て、エラーメッセージを取引データに自動記録。
- **回復力のある API 呼び出し:** `tenacity` ライブラリを用いた指数バックオフ自動リトライにより、一時的な API 制限や通信エラーに自動対処。

## 🏗 技術スタック & アーキテクチャ

- **Language:** Python 3.14+
- **Environment Management:** `uv` (Astral)
- **UI Framework:** Reflex (v0.6.8+)
- **Database:** SQLAlchemy 2.0 Async (`aiosqlite`)
- **Data Validation:** Pydantic V2 (`pydantic-settings` による strict configuration)
- **Resilience:** `tenacity` (Retry), `structlog` (Structured Logging)
- **QA Tooling:** `pytest`, `pytest-asyncio`, `hypothesis` (Fuzzing), `pytest-mock`, `respx`, `ruff`, `mypy`

### クリーンアーキテクチャ (Clean Architecture)
本アプリケーションは、外部フレームワーク（Reflex や SQLAlchemy）の変更に耐えうるよう、依存関係を厳格に制御したレイヤード構造をとっています。

```text
app/
├── app.py              # Reflex エントリポイント
├── config.py           # Pydantic Settings による設定管理 (.env 読み込み)
├── container.py        # 依存関係注入 (Dependency Injection) の定義
├── core/               # アプリケーション共通コアモジュール (Logging, Resilience)
├── domain/             # ドメイン層 (Pydantic V2 エンティティ、モデル、インターフェース)
│   ├── constants/      # 会計上の定数（税率など）
│   ├── interfaces/     # 各リポジトリの抽象ポート
│   ├── models/         # 仕訳・科目・年度などのピュアなドメインモデル
│   └── prompts/        # OpenAI OCR 用のカスタムプロンプト
├── infrastructure/     # インフラ層 (DB, OCR, PDF生成, バックアップの具象実装)
│   ├── db/             # SQLAlchemy ORM 定義とマイグレーション
│   ├── external/       # OpenAI API, PDF 生成, バックアップ等の外部サービス
│   └── repositories/   # リポジトリパターンによるデータアクセス
├── application/        # ユースケース・アプリケーションサービス層
│   └── services/       # 業務フローのオーケストレーション (仕訳・事業年度・マスタ制御)
└── ui/                 # UI プレゼンテーション層
    ├── pages/          # Reflex ルーティングページ定義
    ├── components/     # 再利用可能な UI コンポーネント群
    ├── di.py           # UI レイヤーでのサービス解決用ヘルパー
    └── view_models/    # Reflex State (Independent SubStates パターン)
```

#### モダナイゼーションによる改善 (Refactoring Outcomes)
- **パッケージインポートの完全絶対パス化:** モジュールの二重ロードによるシングルトンの崩壊や、起動方法の違いによる `ModuleNotFoundError` を防ぐため、すべてのインポートを `app.domain...` のように `app` パッケージを起点とした絶対パスに完全統一。
- **起動時サイドエフェクトの排除:** インポート時にDBのシードが自動実行される危険な動作を廃止し、仕訳ページの `on_mount` ライフサイクルで初めて安全に `seed_accounts()` が呼び出される構造へ変更。
- **ポータブルなパス解決:** storage パスやバックアップパスをカレントディレクトリ依存の相対パスから、Pydantic Settings が保持する `settings.PROJECT_ROOT` をベースとした絶対解決へ変更し、どの環境やディレクトリから起動しても正常に稼働するポータビリティを保証。

## 🚀 クイックスタート (Setup & Running)

### 1. 必要環境
- Python 3.14 以上
- `uv` (Astral) がインストールされていること

### 2. インストール
リポジトリをクローンし、依存パッケージをインストールします。
```bash
git clone https://github.com/bottiLLC/STEN-F.git
cd STEN-F
uv sync
```

### 3. 環境設定 (.env)
ルートディレクトリに `.env` ファイルを作成します（`.env.sample` を参考にしてください）。
```ini
# Database Path (SQLite)
DATABASE_URL=sqlite+aiosqlite:///bookkeeping.db

# OpenAI API Key (AI OCR 機能に必要)
OPENAI_API_KEY=sk-proj-...

# OpenAI 推論設定 (カスタマイズする場合)
OPENAI_DEFAULT_MODEL=GPT-5.6-Luna
OPENAI_REASONING_EFFORT=medium
```

### 4. アプリケーションの起動
最も手軽な起動方法は、ルートディレクトリ直下の `run.bat` の実行です（Windows環境）。

```bash
# コマンドラインからの通常起動
uv run reflex run
```

*   **`run.bat` (Windows):** ダブルクリックで起動します。`.venv` の存在を自動チェックし、なければ自動で `uv sync` を走らせて環境構築から行います。8秒後に自動的にブラウザで `http://localhost:3000` を開きます。
*   **`start.command` (macOS/Linux):** 実行権限を付与 (`chmod +x start.command`) して実行します。

### 5. 自動テストの実行
```bash
uv run pytest
```

## 🧰 運用・保守・データリカバリ (Ops & Maintenance)

本システムは SaaS ではなくローカルでデータが一元管理されるため、バックアップとデータ保護は利用者の責任となります。

### バックアップ対象
データや関連書類を保護するため、以下のファイルおよびフォルダをクラウドストレージや外部ディスクに定期的にバックアップしてください。

1. **`bookkeeping.db` (最重要):** すべての仕訳履歴、残高、年度情報、マスタ設定が保存された SQLite データベースファイル。
2. **`storage/` フォルダ:** 各仕訳に紐づいた、電子帳簿保存法に対応する領収書・請求書（PDF・画像）の実ファイルが保存されています。
3. **`.env`:** API キーを含む接続情報設定ファイル。

*(アプリケーション内の「マスタ管理 ＞ システム」タブからも、これらのファイルを一括してバックアップ ZIP としてダウンロード可能です)*

### 完全リカバリ手順
新しいPC等へ環境を移行・復旧させる手順：
1. 移行先の新しい環境で `git clone` および `uv sync` を行い、システムを起動できる状態にします。
2. **アプリケーションが完全に終了していること**を確認します（稼働中のファイル上書きはDB破損の原因となります）。
3. 定期バックアップしておいた `bookkeeping.db`, `.env`, `storage/` ディレクトリ全体を、移行先のプロジェクトルートフォルダへ配置・上書きコピーします。
4. アプリケーションを起動し、「仕訳履歴」のリストが正しく再現され、各取引の証憑（PDF や画像プレビュー）が正常にリンクされていることを確認します。
